# EXCISE 1.5 simulations

Simulation and benchmarking for `excise15.py`, the Python/numba port of `excise1.5.pl`.
Everything in this directory comes from **simulated data only**. No real
biological datasets are read or written here.

```
simulations/
├── run_xci_skew_sweep.py     # XCI-skew experiment: simulate -> excise15.py -> score
├── run_speed_benchmark.py    # original XCISE vs EXCISE 1.5 Perl / Python / C++ runtime by cell number
├── run_default_tries_benchmark.py  # the same tools at the default -t 100
├── make_figures.R            # all figures (ggplot2); reads results/ only
├── results/                  # numerical results (TSV / CSV) behind every figure
├── figures/                  # PDF + 300 dpi PNG
├── sweep.log, speed.log      # run logs
└── data/                     # simulated BAMs + per-run outputs (git-ignored, regenerable)
```

## Reproduce

```bash
pip install numpy numba pysam          # plus samtools and perl Parallel::ForkManager
python3 simulations/run_xci_skew_sweep.py --reps 10 --jobs 4
python3 simulations/run_speed_benchmark.py --jobs 4
Rscript simulations/make_figures.R     # ggplot2, dplyr, tidyr, readr, patchwork, scales
```

Both runners reuse existing datasets and runs, and never overwrite them. Run the two
experiments one after the other, not at the same time, so that the runtimes are not
measured under CPU contention.

## Designs

**XCI-skew sweep** (`tests/simulate_xci_data.py` with `--assign exact`). Only the
X1:X2 ratio changes between conditions:

| Parameter | Value |
|---|---|
| X1:X2 among **monoallelic** cells | 50:50, 55:45, 70:30, 90:10, 95:5, 99:1 |
| Both cells, as a share of **all** cells | 5% (100 of 2,000) |
| Cells / SNVs | 2,000 / 1,000 on a simulated 5 Mb chrX |
| Coverage | 20–60 reads per cell (mean 40), each cell expresses 3–25 SNVs |
| Allelic noise | 2% of reads show the inactive allele |
| Escape SNVs | 5% (biallelic in every cell) |
| Replicates | 10 per ratio; replicate *k* uses seed 100+*k* for every ratio |
| EXCISE | `excise15.py -t 100 -j 4 -seed <seed> -pretrain` |

At 99:1, the 1,900 monoallelic cells are 1,881 X1 and **19 X2**, so the minority
class is 0.95% of all cells.

**Speed benchmark.** 2,000 SNVs, ~60 reads per cell, and 1,000–16,000 cells × 3
seeds. Both tools run with `-t 4 -j 4 -pretrain`. The 8,000-cell, seed 11 dataset is the
dataset of the originally reported benchmark, which is reused.

## Metrics (`tests/evaluate_xci_sim.py`)

EXCISE's X1/X2 names are arbitrary, so each run gets **one global orientation**,
chosen from the SNV haplotypes. Every SNV and cell metric uses that same mapping.

- **Haplotype accuracy**: correctly oriented / phased non-escape SNVs.
- **Unassigned SNVs**: SNVs that pass the filters but are left `Unk`, reported separately for
  non-escape SNVs and for escape SNVs (where `Unk` is the desired outcome).
- **Cell accuracy**: correct calls / all cells. `Low_coverage` and `Unknown` count as
  errors. Mean per-class recall over X1, X2 and Both is also given.
- **Minority-class recall and precision**: for the true X2 cells.
- **Informative cell recovery**: cells called X1, X2 or Both / all cells, and true
  X1/X2 cells called X1 or X2.
- **Runtime**: wall-clock time of the whole `excise15.py` run.

## Results

Generated by the scripts above. Figures are in `figures/`, and the numbers behind them are in `results/`.

**Speed (Fig. 1, `results/speed_benchmark.tsv`).** Mean speed-up of the full Python run over Perl:
2.5× at 1,000 cells, 4.1× at 2,000, 7.7× at 4,000, 9.6× at 8,000 and 13.7× at 16,000 cells
(geometric mean of 3 datasets each). Perl's time grows roughly in proportion to the number of
cells. The Python optimizer takes 0.04–0.06 s at every size, so its run time is
mostly BAM reading plus about 3 s of numba compilation. The bc2xci output was byte-identical in
10 of 15 runs. In the other 5, both stochastic optimizers reached different local optima,
with Python scoring higher twice, Perl twice and the two tied once. One cell in all 15
runs got a different label.

The **C++ port** (`cpp/excise15`, timed separately on the same 15 datasets, with parallel BAM parsing) was
184×, 188×, 199×, 174× and 188× faster than Perl at 1,000 to 16,000 cells, which is 75× to 14× faster than
Python. At 16,000 cells it took 0.95–0.99 s, against 181–185 s for Perl. Its output was byte-identical to Perl in 12 of 15 runs. In the
other 3 runs (1,000 cells), every cell still got the same label.

**Original XCISE** (`xcise.pl` from Vityay/XCISE @3a1d063, timed with `--xcise`; Fig. 1). It used the same 4 tries
and `-u 4`, so it applies the same SNV filter as EXCISE 1.5. It has no `-j`, `-seed` or `-pretrain`, so its tries run
one after another on one core. Times ranged from 112–127 s at 1,000 cells to 5,086–6,292 s (85–105 min) at 16,000 cells.
Against the original, EXCISE 1.5 was 10–31× faster in Perl, 25–422× in Python and 1,849–5,812× in C++
(geometric means per size). All four tools reached the same best score and the same cell accuracy against the
simulated truth on every dataset of 2,000 cells or more (one 2,000-cell set differed by 2 points out of 84,442).
At 1,000 cells, the original's labels differed from Perl EXCISE 1.5 in 0–2 cells. Mean cell accuracy was 0.998
for all four tools.

**Default tries (`-t 100`, `results/default_tries_benchmark.tsv`, 1,000 cells, seed 11).** The original took
3,362 s (56 min), Perl EXCISE 1.5 290 s, Python 2.6 s and C++ 0.15 s. Best scores were 42,135, 42,131, 42,127
and 42,129, and cell accuracy was 0.996 for all four.

**XCI skew (Figs. 2–5, `results/skew_indep_*`, 10 independent replicates per ratio).**

| X1:X2 | minority cells | haplotype accuracy | cell accuracy, mean [range] | minority recall, mean [range] | non-escape SNVs unassigned |
|---|---|---|---|---|---|
| 50:50 | 950 | 1.000 in all runs | 0.993 [0.991–0.996] | 0.993 [0.988–0.997] | 0.39% |
| 55:45 | 855 | 1.000 | 0.994 [0.992–0.997] | 0.994 [0.991–0.998] | 0.40% |
| 70:30 | 570 | 1.000 | 0.994 [0.993–0.997] | 0.995 [0.988–1.000] | 0.41% |
| 90:10 | 190 | 1.000 | 0.993 [0.990–0.997] | 0.994 [0.984–1.000] | 0.32% |
| 95:5 | 95 | 1.000 | 0.993 [0.989–0.996] | 0.991 [0.968–1.000] | 0.28% |
| 99:1 | 19 | 1.000 | 0.993 [0.990–0.996] | 1.000 [1.000–1.000] | 0.32% |

In all 60 runs, no cell was ever assigned to the wrong X. All 787 cell errors out of 120,000
were monoallelic cells called `Both` (plus one `Unknown`). These are cells whose ≥10% of reads show the
inactive allele by chance at 2% read noise, which falls below the 90% purity threshold. Minority
precision was 1.000 in every run, and all escape SNVs were left unassigned. Under these
conditions, which have adequate coverage and low noise, skew down to 99:1 had no measurable effect.
The paired control (`skew_paired_summary.tsv`) gives identical cell accuracy at every ratio
within each replicate. Harder regimes, with lower coverage, higher noise or fewer SNVs per cell, are
the next experiment.

## Parameter sweep: min UMIs per SNV (`-u`) × discordant penalty (`-p`) (Fig. 6)

`run_param_sweep.py` covers `-u` {1, 2, 4, 6, 10, 15, 20} × `-p` {1, 2, 3, 5, 8, 12, 20} on four regimes, with 5
replicates each and 980 runs in total. Every regime has 2,000 cells (5% Both, X1:X2 = 50:50) and 5% escape SNVs.
All runs use `-t 100 -pretrain`. The runs use `cpp/excise15`, which matches `excise1.5.pl`. Spot checks with the Perl script itself (standard regime, replicate 1): at `-u 10 -p 3` all five outputs were byte-identical. At `-u 2 -p 12` the two reached slightly different local optima (best score 37,010 vs 37,013), but labelled all 2,000 cells the same, with identical cell accuracy and 11.7% vs 11.9% of SNVs left unassigned.
Per-run results are in `results/param_sweep_replicates.tsv`. Means, SDs and ranges are in `results/param_sweep_summary.tsv`.

| Regime | Defaults (`-u 4 -p 5`) cell accuracy | Best setting (cell accuracy) |
|---|---|---|
| Standard (40 reads/cell, 2% noise) | 0.993 | same (0.993 for `-p` 2–8) |
| Low coverage (10 reads/cell) | 0.925 | `-u` 1–6, `-p 8`: 0.929 |
| High noise (10% inactive-X reads) | 0.612 | `-p 8`: 0.702 (any `-u`) |
| Sparse SNVs (3,000 SNVs, 15 reads/cell) | 0.954 | `-u 1` or `2`, `-p 5`: 0.955 |

- **`-p` matters most at its extremes.**
  - `-p 1` is too lenient: escape SNVs get phased (only 3% left unassigned, against 100% at `-p` ≥ 2). They add
    discordant UMIs to every cell, so ~10% of true X1/X2 cells drop below the 90% purity threshold and are called `Both`
    (standard regime: cell accuracy 0.909).
  - High `-p` (12–20) is too strict: more and more SNVs are left unassigned (up to 98% at high noise). `Both` cells
    are lost (recall 0.03–0.30 at `-p 20`).
  - In the sparse regime, high `-p` with low `-u` also mis-phases SNVs (haplotype accuracy 0.77–0.88). It then assigns
    up to 15% of cells to the **wrong X**. The only other setting with wrong-X calls above 1% is `-u 20` in the same regime (2–4.5%).
- **`-u` only matters when SNVs have few UMIs.** With 40 reads/cell, every SNV passes any `-u` up to 20, so the
  results do not change. In the sparse regime, raising `-u` drops SNVs (2,990 SNVs pass at `-u 1`, 1,384 at `-u 10`
  and 108 at `-u 20`). Cells lose evidence and become `Low_coverage`/`Unknown` (cell accuracy 0.20 at `-u 20`).
  A moderate `-u` (6–10) protects against wrong-X calls when `-p` is high.
- **Defaults hold up:** `-u 4 -p 5` is within 0.5 points of the best setting in three of four regimes. The exception is
  high noise, where `-p 8` gains 9 points of cell accuracy, at the cost of leaving 55% of SNVs unassigned.
- **High-noise accuracy is limited by the classification threshold, not these parameters.** With 10% of reads from
  the inactive X, a monoallelic cell's haplotype purity is near the hard-coded 90% cut-off for X1/X2 calls. Most
  errors are true X1/X2 cells called `Both`.
